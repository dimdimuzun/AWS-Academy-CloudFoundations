## AWS Identity and Access Management (IAM)
**Використання IAM для керування доступом до ресурсів AWS**  
- Ресурс – це сутність в обліковому записі AWS, з якою можна працювати  
- Приклади ресурсів: Інстанс Amazon EC2 або бакет Amazon S3  
- Приклад: Контроль, хто може припинити роботу інстансів Amazon EC2  
**Визначення деталізованих прав доступу**  
- Хто має доступ до ресурсу  
- Які ресурси можуть бути використані та що користувач може з ними робити  
- Як ресурси можуть бути використані  
IAM – це безкоштовна функція облікового запису AWS  

## Елементи IAM
- **Користувач IAM**: Особа або додаток, які можуть автентифікуватися в обліковому записі AWS  
- **Група IAM**: Колекція користувачів IAM, яким надано однакові дозволи  
- **Політика IAM**: Документ, що визначає, які ресурси можуть бути використані та рівень доступу до кожного ресурсу  
- **Роль IAM**: Корисний механізм для надання дозволів на виконання запитів до сервісів AWS

## AWS Organizations
**Політики керування сервісами (Service Control Policies, SCPs)**  
- Централизованний контроль над обліковими записами  
- Обмеження дозволів, доступних в обліковому записі, що є частиною організації  
- Забезпечення відповідності облікових записів правилам керування доступом  
- SCPs схожі на політики IAM, але:  
  - Ніколи не надають дозволів  
  - Визначають максимальні дозволи для організації  

## AWS Key Management Service (AWS KMS)
**Функції AWS KMS**:  
- Створення та керування ключами шифрування  
- Контроль використання шифрування в сервісах AWS та додатках  
- Інтеграція з AWS CloudTrail для логування всіх використань ключів  
- Використання апаратних модулів безпеки (HSMs), сертифікованих FIPS 140-2, для захисту ключів  

## Amazon Cognito
**Функції Amazon Cognito**:  
- Управління автентифікацією користувачів  
- Синхронізація даних користувачів між пристроями  
- Контроль доступу до додатків через соціальні мережі або корпоративні системи
